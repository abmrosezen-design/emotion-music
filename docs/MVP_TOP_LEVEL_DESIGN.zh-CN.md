# 情绪音乐推荐网站 MVP 顶层设计文档

> 文档版本：0.1  
> 更新日期：2026-08-27  
> 文档状态：开发前方案  
> 产品形态：移动端优先的响应式网页

## 1. 文档目的

本文档用于统一产品、设计和开发方向，定义第一版网站的产品目标、网站层级、主要功能、推荐逻辑、数据结构、技术方案、隐私边界和验收标准。

本文档描述的是可验证核心创意的 MVP，不包含音乐账号绑定、站内完整音乐播放、自动读取用户歌单等需要音乐平台深度授权的能力。

---

## 2. 产品概述

### 2.1 一句话定义

一个通过简短情绪问答了解用户此刻感受，并推荐一首能够“陪伴当前情绪”的歌曲，再引导用户前往常用音乐平台搜索收听的网站。

### 2.2 核心价值

- 降低用户“想听歌但不知道听什么”的选择成本。
- 推荐的不只是歌曲，也提供一句贴近当前情绪的陪伴文案。
- 不要求用户立刻振作或改变情绪，强调理解、接纳和陪伴。
- 不绑定音乐账号也能完成完整体验，降低使用门槛。

### 2.3 已确认的产品方向

- 采用“网页问答＋歌曲推荐＋跳转平台搜索”的方案。
- 第一版只处理“陪伴当前情绪”，暂不提供“改变当前情绪”的推荐路线。
- 推荐条件包括当前情绪、歌曲语言和歌曲类型。
- 推荐结果保留“情绪总结＋歌曲＋推荐理由”的内容结构。
- 推荐页增加系统生成的情绪寄语。
- 推荐页增加名为“此刻想对你说”的用户输入框。
- 经用户明确同意后，匿名保存输入内容，用于优化后续文案。
- 第一版不登录、不绑定网易云音乐、QQ 音乐或酷狗音乐账号。
- 第一版不在本站播放完整歌曲，只跳转到目标平台搜索。

## 3. 目标用户与使用场景

### 3.1 目标用户

- 想听音乐但暂时不知道选什么的人。
- 希望音乐能够理解或陪伴自己情绪的人。
- 不想花时间浏览歌单、排行榜或大量推荐的人。
- 偏好使用网易云音乐、QQ 音乐或酷狗音乐的用户。

### 3.2 典型使用场景

- 深夜情绪低落，希望听一首不强行鼓励自己的歌。
- 工作后疲惫，希望听一首安静的音乐陪伴休息。
- 感到孤独，希望得到一句温柔的话和一首合适的歌曲。
- 心情很好，希望用音乐延续当下的愉快。
- 情绪复杂、难以描述，希望通过简单选项得到推荐。

## 4. 产品范围

### 4.1 MVP 包含

- 首页及产品介绍。
- 分步骤情绪问答。
- 情绪、语言和曲风选择。
- 基于规则和歌曲标签的推荐。
- 情绪寄语、推荐歌曲及推荐理由展示。
- 跳转网易云音乐、QQ 音乐、酷狗音乐搜索。
- 换一首、重新测试和推荐反馈。
- “此刻想对你说”输入与匿名授权。
- 本地记录用户默认音乐平台和当前问答进度。
- 基础歌曲、文案和反馈管理后台。

### 4.2 MVP 不包含

- 音乐平台账号绑定。
- 读取收藏、歌单、会员状态或收听历史。
- 在本站播放或下载完整歌曲。
- 自动抓取歌词、封面或非官方曲库数据。
- 摄像头、语音、表情或生物识别形式的情绪检测。
- 心理疾病诊断、治疗建议或心理咨询服务。
- 用户社区、评论区、私信和公开动态。
- 复杂机器学习或大模型实时生成推荐。

第一版采用移动端优先、线性任务优先的结构。问答可在单页内分步骤完成，也可映射为独立路由，方便恢复进度和数据分析。

```text

│  ├─ 第二步：歌曲语言
```

## 6. 用户主流程

```text
进入首页
→ 点击开始
→ 选择当前情绪
→ 选择歌曲语言
→ 选择歌曲类型
→ 系统计算匹配歌曲
→ 展示情绪寄语、歌曲和推荐理由
→ 用户选择音乐平台
→ 跳转并搜索“歌曲名＋歌手名”
→ 用户返回后可反馈、换一首或重新测试
```

### 6.1 问答步骤

#### 第一步：当前情绪

建议首批选项：

- 开心
- 平静
- 低落
- 孤独
- 焦虑
- 疲惫
- 愤怒
- 说不清

每个选项应使用文字、简洁图形和颜色共同表达，不能只依赖颜色，以保证可访问性。

#### 第二步：歌曲语言

- 普通话
- 粤语
- 英语
- 日语
- 韩语
- 其他
- 随机

#### 第三步：歌曲类型

建议首批选项：

- 流行
- 摇滚
- R&B
- 民谣
- 蓝调
- 经典
- 轻音乐
- 电子
- 说唱
- 随机

“经典”更接近年代或长期流行属性，并非严格音乐类型。数据层应将其作为独立标签保存，界面上可以继续作为方便用户理解的入口。

## 7. 推荐结果页

### 7.1 内容顺序

1. 系统生成的“给此刻的你”。
2. 当前情绪与选择总结。
3. 歌曲名称和歌手。
4. 推荐理由。
5. 网易云音乐、QQ 音乐和酷狗音乐搜索按钮。
6. “符合此刻”“不太符合”“换一首”和“重新测试”。
7. “此刻想对你说”用户输入区。

### 7.2 推荐展示示例

> **给此刻的你**  
> 今天不必急着变好，先允许自己安静一会儿。

> 你现在有些低落，想听粤语经典歌曲陪伴这种情绪。

> **推荐：陈奕迅《夕阳无限好》**  
> 推荐理由：克制而温柔，不急着让你振作，只是陪你慢慢消化此刻。

### 7.3 “此刻想对你说”输入区

字段名称必须保留为：**此刻想对你说**。

建议占位文案：

> 如果愿意，可以留下一句话。你的感受将帮助我们写出更贴近人心的文案。

交互要求：

- 输入为可选项，不能阻挡歌曲推荐与平台跳转。
- 建议限制为 300 个字符。
- 提交前显示“允许匿名用于优化文案”勾选项，默认不勾选。
- 明示“请勿填写姓名、电话、住址等个人敏感信息”。
- 未授权时不上传原始文本。
- 提交成功后提供撤回或删除入口。
- 后台不得把原始内容公开展示给其他用户。

## 8. 推荐逻辑

### 8.1 第一版原则

第一版使用可解释的规则推荐，不依赖 AI 模型。歌曲由运营人员建立标签，系统根据用户选择计算匹配分数，再在高分歌曲中加入少量随机性，避免每次得到完全相同的结果。

### 8.2 情绪维度

建议把情绪映射为两个基础维度：

- 愉悦度：负面至正面。
- 能量值：平静至激动。

还可附加：

- 情绪名称。
- 适合的陪伴语气。
- 不建议使用的表达方式。

例如，“低落”对应较低愉悦度和中低能量；文案应温柔、克制，避免使用“你应该开心起来”等强制表达。

### 8.3 歌曲标签

每首歌至少包含：

- 歌曲名称。
- 歌手。
- 语言。
- 曲风。
- 年代或“经典”标签。
- 愉悦度。
- 能量值。
- 适合的情绪。
- 推荐理由模板或人工推荐理由。
- 三个平台的搜索关键词或已验证链接。
- 是否启用。

### 8.4 建议评分模型

```text
总分 =
情绪匹配 45%
+ 语言匹配 25%
+ 曲风匹配 20%
+ 用户历史反馈 5%
+ 随机探索 5%
```

MVP 没有用户历史时，将该部分权重并入情绪匹配。随机选择范围应限制在最高分的一小组歌曲中，而不是从全部曲库随机。

### 8.5 换一首规则

- 同一轮问答中避免重复推荐。
- 优先从相同情绪、语言和曲风的候选歌曲中选择。
- 候选不足时，依次放宽曲风、语言，不优先放宽情绪。
- 如果必须放宽条件，应在界面上自然说明。

## 9. 情绪文案策略

### 9.1 MVP 文案来源

- 第一版优先使用人工编写并审核的原创文案库。
- 根据情绪、能量和歌曲特征组合或选择文案。
- 不自动抓取歌词。
- 未取得授权前，不把歌曲歌词作为核心内容库。

### 9.2 文案语气原则

- 不评价用户情绪对错。
- 不强迫用户立刻振作。
- 不暗示网站能够诊断心理状态。
- 不使用保证疗效的表达。
- 不制造依赖感，例如避免“只有我理解你”。
- 对严重自伤、他伤或紧急危险表达设置安全提示与人工审核机制。

### 9.3 用户反馈如何用于优化

文案优化可以参考：

- 情绪类别与用户原始表达之间的常见主题。
- 用户对推荐是否“符合此刻”的反馈。
- 哪类寄语对应更高的歌曲跳转率。
- 哪些表达经常伴随“不太符合”。

分析时优先使用聚合标签和去标识化摘要；原始文本仅供受限人员在必要范围内查看。

## 10. 音乐平台跳转方案

### 10.1 MVP 跳转策略

- 搜索关键词统一生成为“歌曲名＋歌手名”。
- 每个平台由独立适配器生成搜索地址。
- 优先使用经过验证的 HTTPS 搜索链接。
- 如果平台支持且稳定，可使用歌曲详情链接或深度链接。
- APP 未安装或链接失效时，回退到平台网页搜索。
- 用户选择的默认平台保存在浏览器本地。

### 10.2 平台按钮

- 网易云音乐搜索
- QQ 音乐搜索
- 酷狗音乐搜索

### 10.3 实施注意事项

- 平台链接格式可能变化，需要独立配置并定期检查。
- 不依赖逆向、抓包或未经授权的非官方接口。
- 不抓取和保存完整音频。
- 封面、歌词等素材只有在确认授权或符合平台使用规则后才展示。

## 12. 技术架构

### 12.1 推荐技术栈

| 层级 | 推荐技术 | 用途 |
|---|---|---|
| 前端框架 | Next.js + React + TypeScript | 页面、交互、路由和服务端接口 |
| 样式 | Tailwind CSS + CSS Variables | 响应式布局、主题和设计令牌 |
| 表单与校验 | React Hook Form + Zod | 问答、输入和数据校验 |
| 后端接口 | Next.js Route Handlers | 推荐、反馈、管理接口 |
| 数据库 | PostgreSQL | 歌曲、文案、推荐和反馈数据 |
| ORM | Prisma | 数据模型和数据库访问 |
| 状态保存 | 浏览器 localStorage + 服务端会话 | 问答进度、默认平台、匿名会话 |
| 测试 | Vitest + Playwright | 单元测试和关键流程端到端测试 |
| 部署 | Docker + 云服务器 | 环境一致性和正式部署 |
| 监控 | 结构化日志＋基础错误监控 | 定位跳转、推荐和接口问题 |

### 12.2 MVP 简化方案

为了快速完成第一版原型，可以先使用：

- 本地 JSON 保存约 50 首测试歌曲。
- 本地 JSON 保存原创情绪文案。
- 浏览器 localStorage 保存问答进度和默认平台。
- 暂不建设数据库和管理后台登录。
- 反馈提交接口先写入开发环境数据库或模拟接口。

核心体验确认后，再迁移到 PostgreSQL 和正式后台，避免过早建设复杂基础设施。

## 13. 管理后台功能

后台不是首个可视化原型的阻塞项，但正式收集反馈前应具备最小管理能力。

### 13.1 歌曲管理

- 新增、编辑、停用歌曲。
- 设置语言、曲风、情绪、能量和年代标签。
- 编辑推荐理由。
- 验证各平台搜索或歌曲链接。

### 13.2 文案管理

- 新增和编辑原创情绪寄语。
- 标记适用情绪和语气。
- 审核、启用和停用文案。
- 查看文案对应的“符合此刻”比例。

### 13.3 反馈管理

- 查看聚合反馈统计。
- 查看已授权的匿名文本。
- 标记敏感、无效或需要删除的内容。
- 执行用户删除请求。
- 导出不含身份信息的汇总数据。

## 14. 隐私、安全与合规原则

- 情绪和用户自由输入可能包含敏感内容，应遵循最小必要原则。
- 用户不提交文字或不同意保存时，仍可完整使用歌曲推荐功能。
- 保存前明确说明数据用途、保存期限和删除方式。
- 授权不得与“开始听歌”或跳转音乐平台捆绑。
- 前后端同时限制输入长度并防止脚本注入。
- 原始输入加密存储，后台实行最小权限访问。
- 日志中不得记录用户输入全文。
- 正式上线前准备隐私政策、用户协议、联系方式和删除渠道。
- 产品应注明“仅提供音乐推荐与情绪陪伴，不构成心理诊断或治疗建议”。
- 若公开面向中国大陆用户运营，应在上线前确认域名、服务器、ICP备案、APP/小程序相关要求及第三方平台规则。

## 15. 视觉与交互方向

### 15.1 建议风格

- 温暖、安静、克制。
- 以夜色、柔和渐变和低饱和颜色为基础。
- 不采用明显医疗、心理测试或诊断视觉。
- 页面一次只突出一个主要动作，降低选择压力。

### 15.2 交互原则

- 问答进度始终可见。
- 每一步支持返回修改。
- 选项文字清晰，不使用过度抽象的情绪图标。
- 推荐生成动画控制在短时间内，不能故意延长等待。
- 结果页的歌曲、理由和平台按钮优先于数据输入框。
- 所有关键操作支持键盘访问，并保证合理对比度。

## 16. 数据指标

MVP 优先验证以下指标：

- 首页到完成问答的转化率。
- 各问答步骤的退出率。
- 推荐结果的“符合此刻”比例。
- 换一首比例。
- 音乐平台跳转率。
- 每个平台的跳转成功情况。
- “此刻想对你说”的自愿提交率。
- 用户输入授权率和删除请求处理情况。

不应把“用户提交更多情绪内容”本身作为增长目标，避免诱导用户披露不必要的私人信息。

---

## 17. MVP 验收标准

### 17.1 功能验收

- 用户可在手机和桌面浏览器完成三步问答。
- 每种情绪至少有可推荐歌曲，不能出现空结果。
- 推荐结果与选择的语言、曲风和情绪大体一致。
- 用户可换一首且同一轮不立即重复。
- 三个平台按钮能使用正确的歌曲名和歌手发起搜索。
- 用户可保存默认音乐平台。
- 用户可反馈推荐是否符合此刻。
- “此刻想对你说”不填写也不影响核心流程。
- 未勾选匿名使用授权时，原始输入不会上传。
- 页面刷新后可恢复未完成的问答或安全地重新开始。

### 17.2 质量验收

- 移动端常见屏幕宽度下无横向滚动。
- 核心页面加载快速，无大体积音频或视频资源。
- 推荐规则有自动化测试。
- 用户输入经过长度和安全校验。
- 外部平台链接使用安全打开方式。
- 隐私说明和删除渠道可从结果页访问。

## 18. 开发阶段建议

### 阶段一：可交互视觉原型

- 完成首页、问答和结果页。
- 使用本地测试歌曲和文案。
- 实现响应式布局和主要交互。
- 验证整体氛围和使用流程。

### 阶段二：可用 MVP

- 接入推荐规则。
- 验证三家平台跳转。
- 增加匿名反馈和授权流程。
- 建立基础数据库和管理能力。
- 完成隐私说明与安全处理。

### 阶段三：小范围测试

- 邀请真实用户体验。
- 根据跳出率、匹配反馈和访谈优化问题数量。
- 扩充到约 200–500 首人工审核歌曲。
- 优化情绪文案和推荐理由。

### 阶段四：正式运营准备

- 完善后台、监控、备份和删除流程。
- 处理部署、备案和平台规则要求。
- 评估是否与音乐平台开展正式合作。
- 再决定是否加入账号、个性化和 AI 能力。

## 19. 开发前非阻塞事项

以下事项尚可后续调整，不阻塞原型制作：

- 正式产品名称与 Logo。
- 最终品牌颜色和字体。
- 首批歌曲的具体清单。
- 用户文本的正式保存期限。
- 正式部署平台与域名。
- 是否在后续加入“改变当前情绪”路线。

原型阶段建议使用临时名称、原创占位文案和人工整理的测试歌曲，待核心体验确认后再正式定稿。

## 20. 顶层结论

本项目的第一版应聚焦一个清晰闭环：

> 用户表达此刻情绪 → 网站理解偏好 → 给出一句合适的话和一首合适的歌 → 用户前往熟悉的平台收听 → 用户反馈是否符合此刻。

技术上采用规则推荐、人工标注曲库和平台搜索跳转即可完成核心验证。第一版不需要音乐账号绑定、复杂 AI 或站内播放。产品真正需要打磨的部分是情绪表达是否自然、推荐是否可信，以及用户是否愿意在情绪出现时再次回来。
